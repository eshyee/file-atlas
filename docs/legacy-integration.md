# 原脚本整合说明

FileAtlas 将原目录中的分类、跨盘去重、单盘去重和跨盘合并能力整合为一套界面与安全执行流程。原脚本保留在用户本地，公开仓库仅包含整合后的源码，不上传历史日志、扫描数据库、个人文件路径或附带的第三方程序。

## 分类版本对应

| 原版本 | 变化 | 整合方式 |
| --- | --- | --- |
| `all_classify_cleanup.py` | 图片、视频、音频、文档分类；工程保护；分类后清理空文件和空目录 | 保留识别规则和工程保护；移除自动清理 |
| v2 | 兼容 ExifTool 分组字段，如 `EXIF:Make`；补充 Sony 型号回退和相机文件名识别 | 保留 |
| v3 | 对 Unknown 类别重新读取元数据并分类 | 统一识别规则，使用预览后的新分类计划 |
| v4 | 已分类媒体重新分类；媒体内日期和文件名日期解析；修正 PDF 误识别 | 保留日期、类型识别规则；已有文件由统一计划处理 |
| v5 | 从媒体内部日期、文件名日期、文件创建时间中选取最早有效日期 | 保留；界面预览显示时间来源 |
| v6 | 媒体目录改为时间优先：类型 → 年 → 月 → 设备/来源 | 采用此结构 |

所有版本的文档内嵌代码相同。文档按格式和月份分类，例如 `document_classify/PDF/2024-09/report.pdf`。JSON、YAML 等结构化文件默认不参与分类，避免拆散配置文件。

`metadata_media.py` 和 `metadata_documents.py` 使用 Python AST 从 v6 内嵌字符串提取，移除了原执行入口、复制、删除、解压和清理函数。它们只读取元数据、识别类型、分析压缩包目录和计算建议路径。公开代码不再执行字符串形式的嵌入脚本。

`classification.classify_file(path, include_structured=False)` 返回 `category`、`relative_path`、`date_source`，未知扩展名返回 `None`。类别为 `picture`、`video`、`audio`、`document`。媒体保持 v6 的最早日期原则；Windows 使用创建时间，其他平台有出生时间时使用出生时间，否则明确使用修改时间，避免把 Unix 的 inode 变更时间当作创建时间。

整合时修正两处有歧义的扩展名：RED 相机 `.r3d` 按视频处理；`.ts` 只有在文件头的三个连续 MPEG TS/M2TS 数据包同步位置均检测到 `0x47` 时才按视频处理，否则保留原文件。此规则也保护独立存在、尚未处于工程目录中的 TypeScript 文件。

## 去重和合并对应

| 原脚本 | 原能力 | 整合后的安全边界 |
| --- | --- | --- |
| `cross_drive_dedup.py` | 大小 → 文件首尾快速哈希 → 完整 SHA-256；跨目录保留策略；扫描与执行分离 | 完整 SHA-256 才能认定重复；执行时重新核验 |
| `merge_to_drive.py` | 增加安全复制合并、同内容跳过、同名冲突改名和会话记录 | 先预览，复制验证后报告结果 |
| `merge_to_drive_v2.py` | 增加单目录去重及 smart/shortest/oldest/newest 保留策略 | 单目录和跨目录使用同一验证流程 |

旧版去重采用永久删除；旧版分类会在确认目标内容后删除源文件；旧版复制会删除碰巧重名的 `.part` 文件。整合版的执行和恢复由新的安全引擎负责，不调用这些旧函数。

## 默认保留的文件

- ZIP 保持完整。旧版高置信纯媒体/文档 ZIP 会解压后删除原包；自动解压和删包不纳入默认 GUI 流程。模块中的 ZIP 分析仅读取目录，不解压成员。
- 不自动删除 0 字节文件或空目录。0 字节文件可能是工程标记、占位文件或软件所需文件。
- 工程目录、系统目录、符号链接和 Windows Junction 由统一遍历规则保护。
- 应用状态与缓存目录受到保护；NTFS 附加数据流（包括下载来源标记）或 EFS 加密文件直接跳过，避免自定义字节复制丢失额外信息。
- 扫描、元数据读取失败和哈希失败应作为跳过或错误报告，不能据此删除源文件。

## 人脸索引整合

补充的 `face_photo_index.py` 提供图片扫描、InsightFace 特征提取、DBSCAN 聚类和 CSV 导出。File Atlas 保留“原图只读、索引在本机、不猜姓名和人口属性、可增量更新”的目标，但没有直接执行或复制原脚本。

整合版将人脸数据写入应用状态目录中的独立 SQLite 数据库，不向图片目录写 CSV 或缩略图。每次更新先建立一个完整代次，聚类完成后才原子切换；取消或失败时上一版索引继续可用。缓存以照片完整 SHA-256、模型 SHA-256 和推理参数共同决定，避免只看文件大小/修改时间或换模型后混用特征。

聚类不采用 `DBSCAN(min_samples=1)` 的传递链。候选人脸必须与组内每个成员达到阈值，而且同一张照片中的两张不同人脸不会自动归入同一组。这会更倾向于拆分，用户界面也只称其为“相似人脸组”，不用于身份认证。

原脚本默认使用 InsightFace `buffalo_l` 并可能首次联网下载；其公开预训练权重仅限非商业研究。整合版使用本地 OpenCV YuNet/SFace 接口，运行时不联网下载模型。Windows 完整版构建从固定 OpenCV Zoo 提交下载并校验模型，许可证和哈希记录在 `THIRD_PARTY_NOTICES.md`。

图片在读取、推理和生成内存缩略图前后都会核验身份与内容。RAW 暂不进入人脸索引；HEIC/HEIF 需要可选 `pillow-heif`。默认 48 MP、256 MiB 解码上限用于约束异常输入的资源消耗。

## 媒体预览整合

预览只能引用当前扫描计划中的文件 ID，不能提交本地路径。服务会重验来源根目录、扫描快照和只读文件句柄，再发放短期同源媒体凭据。浏览器原生格式支持 Range/HEAD；其他格式在本机用 Pillow 或可选 FFmpeg 生成有大小、时长和并发上限的临时预览。转换器从授权句柄的标准输入读取，不允许网络协议或相邻文件发现。

## 依赖与发布

Pillow 用于常见图片元数据回退；`pillow-heif` 可选，用于 HEIC/HEIF。OpenCV 与 NumPy 用于可选人脸索引。ExifTool、FFmpeg 和 FFprobe 为可选的本地工具，可放在应用目录或加入 PATH，运行时不会自动下载。ExifTool 使用有超时的 CLI 读取方式，不启用长期驻留子进程，也不依赖 PyExifTool。用户可按需从工具官网安装，第三方二进制与 Perl 分发包不纳入公开仓库。

旧目录中的 `*_logs/`、`session_*/`、CSV 报告和 SQLite 数据库含个人文件路径或处理历史，必须留在本机。原 Python 源码审查未发现硬编码账号、密码、API 密钥或访问令牌；示例盘符是说明文字，不是默认执行目标。
